THIS HOST
remilia.org is the corporate and literature host of Remilia Corporation (Remigumi-guchi Digital, LLC). Corporate pages are hand-authored static HTML. Updates, Press, Thought, and Archive are structured posts compiled to HTML with Markdown and plain-text siblings, RSS 2.0, Atom 1.0, sitemaps, and llms.txt maps. The canonical host is https://remilia.org/ (non-www). The digital storefront is remilia.com, the community encyclopedia is wiki.remilia.org, and the software network is remilia.net.

WHERE TO GO

remilia.org — corporate pages and literature (/updates, /press, /thought, /archive). remilia.com — fashion, brand, shop, and culture; news and events live under /a/news and /a/events. remilia.net — Remilia software products and engineering blog. wiki.remilia.org — encyclopedia; cite Remilia Corporation for facts. HOW THIS SITE IS BUILT

The corporate pages use standards-compliant HTML5 and CSS without a client framework. Markup has one H1, semantic landmarks, a skip link, and a declared document language. Discovery uses rel=canonical, Open Graph, Twitter Cards, RSS 2.0, Atom 1.0, sitemap.xml, robots.txt, llms.txt, llms-full.txt, and JSON-LD using the AboutPage schema. Images carry alternative text where they convey content. The site honors prefers-reduced-motion and prefers-contrast: more. Every page remains readable without JavaScript. JavaScript is limited to in-page hash scrolling in headings.js, the homepage inspirations rotator in inspo.js, and the careers job board in jobs.js.

Authors maintain the readable HTML in deploy/src/. Shared head tags live in _partials/, then merge during bake:corp. bake:fx creates an inert layer-fx copy while CSS paints only layer-base through the print-fx filter, leaving type and borders single. Crest and photo cells use the dither-3 filter.

The source code is hosted at remiliacorporation/remilia-org and licensed under the Viral Public License.

HOW THE BLOG IS DESIGNED

The blog is not a web application that happens to contain articles. It is a publishing system that resolves into documents. Sanity Studio is the editorial source, not a production runtime. At build time, published records become complete HTML pages containing their text, navigation, citations, metadata, and links before the browser runs a script. CSS controls presentation and native interface state; JavaScript may enhance a document but never owns its route or its contents. Static here means resolved and addressable, not inert.

One content graph serves three hosts. A post's channel selects its section, origin, URL, metadata, and visual identity; the shared renderer supplies the same document contract everywhere: main, article, one h1, machine-readable time, stable heading fragments, a table of contents, and canonical and alternate links. Tag and author archives, static pagination, and previous and next links make the archive traversable as hypertext rather than as an infinite feed. An interlink remains an ordinary a element, but exposes a card built from the target record's cover, title, and description. An outlink is visibly marked and declares rel="external noopener". No private router or client cache stands between a reader and a URL.

Interaction begins with browser primitives. Sidenote text is always present in the HTML: on a wide screen CSS places it in the margin beside its reference; on a narrow screen a checkbox, :target, and hover state open it over the text. Link cards work on hover and focus. The theme dial is a group of real inputs whose state CSS can read with :has(). Small deferred scripts add section filtering, rail search, current-heading indication, copy controls, touch behavior for link cards, and an event-gallery lightbox. Remove them and the documents still read, link, paginate, and expose every note.

The interface is deliberately narrow and finite. An index is a set of paginated cards; an article is a 560-pixel reading measure flanked on large screens by a contents and citation rail and an adjacent-post rail. Those rails collapse rather than squeeze the prose. Color is one --hue: paper, ink, focus states, the fixed dot lattice, and the image dither are calculated in oklch(), with compensation where yellow and cyan would otherwise lose contrast. Remilia.org is baked red on light paper with a dense lattice; remilia.com red on dark with no lattice; remilia.net blue on light with a sparse lattice. Reader choices override those host defaults before first paint. Photographs are made to belong to the page — grayscale, ordered halftone, pixel ink, current hue — rather than sitting above it as untouched rectangles.

Interoperability is an output, not a promise. Every post is emitted as HTML, Markdown, and plain text. Every section publishes crawlable indexes and directories, RSS, Atom, sitemaps, and llms.txt. Discovery metadata and JSON-LD describe the same records; aliases become redirects; external archive entries retain their original canonical outlet. The bake fingerprints assets, refuses unreadable or unexpectedly empty source data before replacing a section, and checks internal links across the finished host. Publishing reruns that bake, so the human, feed, crawler, and machine-readable views are regenerated together. The source is released under the Viral Public License.
